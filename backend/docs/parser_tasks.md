## 1. Модальные формы (КРИТИЧНО)

### Проблема

Формы заявок в модальных окнах («Оставить заявку», «Записаться», попапы) НЕ
попадают в `pages[].forms`. Парсер снимает только статический DOM после
`domcontentloaded`, а такие формы рендерятся в DOM **только по клику** на кнопку
(conditional rendering у React/Vue/конструкторов — Tilda, Webflow и т.п.).

### Доказательство (neurolife.tech)

Прогон через Playwright в контейнере crowler:

| Момент | `<form>` | `<input>`/`<textarea>` |
|--------|----------|------------------------|
| Сразу после `domcontentloaded` | 0 | 0 |
| +2 сек ожидания | 0 | 0 |
| **После клика «Оставить заявку»** | **1** | **4** |

То есть формы НЕТ в DOM до клика — это не скрытый элемент, а отсутствующий.
Эмуляция браузера (Chromium запущен, JS выполняется) тут не помогает: нужно
именно ВЗАИМОДЕЙСТВИЕ. На сайте 4 кнопки-триггера: «Оставить заявку» ×3,
«Записаться на консультацию» — все ведут к формам сбора ПДн, сейчас невидимым
для аудита.

### Что сделать

После загрузки страницы и снятия статических форм — дополнительно:

1. Найти кнопки-триггеры модалок по тексту (регистронезависимо, подстрока):
   `оставить заявку`, `записаться`, `заказать звонок`, `обратный звонок`,
   `связаться`, `консультаци`, `задать вопрос`, `получить`, `отправить заявку`,
   `заказать`, `регистраци`, `записать`.
   Искать в `button`, `a`, элементах с `role="button"`, `[onclick]`.
2. Для каждого уникального триггера: кликнуть, подождать появление формы
   (`page.wait_for_selector('form, [class*=modal] input', timeout≈3000)`),
   снять `detect_forms` с нового состояния DOM, закрыть модалку (Esc / клик по
   крестику / клик по оверлею), перейти к следующему триггеру.
3. Дедуп форм: одна и та же форма часто открывается несколькими кнопками —
   дедуплицировать по составу полей (`fields[].name`) + `action`.
4. Защита от зацикливания: лимит на число кликов за страницу (например, 8),
   таймаут на всю фазу взаимодействия.

### Дополнительно

Проверять не только `<form>`, но и контейнеры с `<input>`/`<textarea>` ВНЕ
`<form>` — многие конструкторы не оборачивают поля в `<form>` (поля + кнопка
сабмита просто лежат в `<div>`).

### Acceptance

- [ ] Скан `neurolife.tech` находит форму «Оставить заявку» в `pages[].forms`
      с `pii_kinds`, включающими `name`, `phone`, `email`.
- [ ] `summary.forms_total > 0`, `summary.forms_collecting_pii > 0` для этого сайта.
- [ ] Сайт без форм (статический лендинг) по-прежнему даёт `forms_total: 0`
      (нет ложных срабатываний от случайных кнопок).

## 2. Детерминированный обход (для воспроизводимости оценки)

### Проблема

Два скана одного сайта могут вернуть разный НАБОР обойдённых страниц (BFS при
упоре в `max_pages` отбирает разные страницы) → разный CrawlJSON → разная
оценка LLM. Бэкенд канонизирует вход (сортирует), но если набор страниц
отличается — отчёт всё равно «дрожит».

### Статус

Часть уже сделана на стороне бэкенда и в `crawler.py` (сортировка seeds и
followable-ссылок — `sorted(...)`). Осталось закрепить и дополнить:

### Что сделать

1. Убедиться, что обход BFS детерминирован: ссылки на каждом уровне
   сортируются по нормализованному URL перед постановкой в очередь
   (стартовая страница — всегда первая). *(базово уже внесено)*
2. Сортировать выходные массивы перед отдачей: `pages[]` по `url`,
   `summary.trackers[]` по `name`, `summary.third_party_domains[]`,
   `policy_documents[]` по `url`.
3. (опционально) Ретрай страниц, упавших по таймауту, 1-2 раза — убирает
   дивергенцию из-за сетевых сбоев.

### Acceptance

- [ ] Два последовательных скана СТАТИЧЕСКОГО сайта дают одинаковый набор
      `pages[].url` и одинаковый порядок `summary.trackers`.
- [ ] Diff двух CrawlJSON (после вырезания `meta.scan_id`, `started_at`,
      `finished_at`, `duration_ms`) — пустой для статического сайта.

> Замечание: для динамических сайтов (Wikipedia, соцсети — разный контент при
> каждом заходе) полный детерминизм недостижим и не требуется. Целевая
> аудитория — бизнес-сайты SMB, которые статичны.

## 3. Детекция трекеров на крупных сайтах

### Проблема

Детектор находит трекер только если он с ДРУГОГО домена. На крупных сайтах
(YouTube, VK, Ozon) аналитика хостится на собственных доменах → трекеры не
обнаруживаются, отчёт показывает «0 трекеров».

### Что сделать

1. В `signatures.py` добавить сигнатуры платформ независимо от домена:
   `googletagmanager.com`, `google-analytics.com`, `doubleclick.net`,
   `mc.yandex.ru`, `top-fwz1.mail.ru`, `vk.com/rtrg`, `connect.facebook.net`,
   `analytics.tiktok.com`, `static.hotjar.com`, `www.clarity.ms` и т.п.
2. Убрать жёсткий критерий «домен трекера ≠ base_domain» → заменить на
   «совпадает с известной платформой».
3. Детекция по cookies: если выставлены `_ga`, `_gid`, `_ym_uid`, `_fbp`,
   `_ttp`, `_hjSessionUser_*` и т.п. — добавлять в `trackers[]` даже без
   видимого скрипта.
4. `cross_border`: Google/Meta/TikTok/Hotjar/Clarity = true; Yandex/VK/Mail.ru/
   Bitrix24 = false. Mapping держать в `signatures.py`.

### Acceptance

- [ ] `youtube.com` → `pages[].trackers.length >= 3`.
- [ ] `vk.com` → найден Top.Mail.Ru или VK Pixel.
- [ ] Сайт-визитка без аналитики → `trackers: []`.

- Сортировка seeds и followable-ссылок в BFS (база задачи №2).
