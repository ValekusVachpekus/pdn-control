# Рабочий процесс

Документ фиксирует правила работы с репозиторием. Они обязательны для всех изменений,
кроме единственного начального setup-коммита.

Команды локального запуска и проверок перед PR (setup / verify), ограничения
безопасности и структура репозитория — в [`AGENTS.md`](AGENTS.md). Состояние передачи
продукта заказчику — в [`docs/customer-handover.md`](docs/customer-handover.md).

## Ветки и Pull Request

- Прямые пуши в `main` запрещены — все изменения идут через Pull Request.
- На каждое изменение — отдельная ветка. Имя: `<номер-issue>-краткое-описание`
  (например, `42-add-login-form`). Ветку создавайте со страницы связанной issue.
- Один PR — одно сфокусированное изменение.
- PR линкуется к issue (`Closes #<номер>`). Исключение — автоматические PR обновления
  зависимостей: они без issue, но тоже проходят ревью и проверки.
- Нужен апрув **минимум одного другого** участника. Автор не апрувит свой PR.
- Перед мерджем проверьте выполнение критериев приёмки из issue.
- Тип мерджа — **merge commit** (squash и rebase отключены).
- Не переписывайте историю и не удаляйте PR/ревью до окончания оценки соответствующего
  ассайнмента. Переписывание истории допустимо только для удаления случайно
  закоммиченных секретов (см. ниже).

## Issue

- Используйте формы: User Story, Задача/PBI, Баг-репорт (`.github/ISSUE_TEMPLATE/`).
- Создание пустых issue отключено.

## CHANGELOG

- Ведём `CHANGELOG.md` по [Keep a Changelog](https://keepachangelog.com/).
- Все правки, видимые пользователю, добавляются в секцию `[Unreleased]` с категорией
  `Added` / `Changed` / `Deprecated` / `Removed` / `Fixed` / `Security`.
- В PR-шаблоне отметьте ровно один пункт чеклиста changelog.

## Релизы

- Версионирование — [SemVer](https://semver.org/), теги с префиксом `v` (`v0.1.0`).
- Тег и релиз указывают на коммит защищённой ветки `main`.
- При релизе перенесите записи из `[Unreleased]` в датированную секцию версии и
  заведите новую пустую `[Unreleased]`.
- Теги, привязанные к сданным MVP-этапам, не двигаем и не удаляем до оценки курса.
- В релиз прикладываем runnable-артефакт, инструкции запуска и публичное демо-видео (<2 мин).

## Секреты и чувствительные данные

- Не коммитьте `.env`, ключи, ПДн, реальные учётные данные. Используйте `.env.example`.
- Если секрет всё же попал в репозиторий: немедленно отзовите/смените его, при
  необходимости временно сделайте репозиторий приватным, уведомите TA, удалите данные
  из файлов и истории, приватно задокументируйте инцидент для TA.

## Проверки (CI)

- Lychee проверяет ссылки во всех Markdown-файлах на PR и push в `main`.
- Локально: `lychee --config lychee.toml './**/*.md'`.
