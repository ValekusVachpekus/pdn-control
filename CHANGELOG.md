## [1.2.0] - 2026-07-04

Инкремент спринта Assignment 5 (milestone #3) — **MVP v2: «аутентификация и архитектура»**.
Реальная аутентификация (соц-вход Яндекс/ВК + passwordless-вход по коду на e-mail),
закрытие замечаний клиента с UAT `MVP v1` и поддерживаемая документация архитектуры
(static/dynamic/deployment views + ADR) и процесса разработки — без ослабления quality-гейтов
Assignment 4.

### Added

- Вход и регистрация по одноразовому коду на e-mail (passwordless / OTP) как альтернатива паролю: двухшаговый экран входа (e-mail → 6-значный код) с кнопкой повторной отправки и кулдауном. Код хранится только bcrypt-хэшем, живёт 10 минут, ограничен числом попыток; запрос кода защищён rate-limit по e-mail и IP и не раскрывает наличие аккаунта. Отправка писем — через Resend (без локального SMTP); без ключа работает DEV-режим с выводом кода в лог. Отработавшие коды (использованные/протухшие) периодически вычищаются фоновой задачей celery beat (#55).
- Автотесты под MVP v2 в CI-гейте: юнит-тесты аутентификации (bcrypt + JWT — подпись, подмена, просрочка) и rule-engine/отчёта (cookie-нарушения адресованы маркетологу, точки сбора ПДн, разбивка скоринга по роли). Модуль `auth.py` добавлен в гейт покрытия критических модулей; обновлены `docs/testing.md` и QRT (#110).
- Реальный соц-вход через Яндекс и ВКонтакте (OAuth 2.0 redirect-flow, вместо заглушки): кнопка ведёт на экран согласия провайдера, бэкенд обрабатывает колбэк (проверка state/CSRF, обмен кода на токен, чтение профиля), находит/создаёт/линкует аккаунт, фиксирует согласие при первой регистрации (152-ФЗ ст. 9) и ставит httpOnly-сессию. ВК — по протоколу VK ID (OAuth 2.1 + PKCE). Включается заданием client_id/secret в `.env.secret` (#72).

### Fixed

- Отчёт: нарушения по cookie-баннеру (`cookie_no_reject`) и отсутствию cookie-уведомления (`no_cookie_notice`) адресуются роли «Разработчик», а не «Маркетолог» — реализация баннера/уведомления является технической задачей (#103).
- Проверка без входа больше не открывает экран загрузки: незалогиненному пользователю предлагается войти/зарегистрироваться, а после входа проверка введённого сайта запускается автоматически (#99).
- На пустом экране истории добавлена заметная кнопка «Новая проверка» — очевидный путь обратно на главную (#100).
- В отчёте убран бесполезный «0» штрафа для неприменимых проверок: блок штрафа скрывается, ненулевые суммы отображаются как прежде (#101).
- Блок «Точки сбора ПДн» больше не выглядит пустым: для каждой найденной формы показывается расположение («Главная страница» или путь страницы) во всех режимах (#102).

## [1.1.0] - 2026-06-27

Инкремент спринта Assignment 4 (milestone #2) — «качество и автоматизация»: измеримые
требования к качеству и автотесты к ним, CI-гейт, обновлённый Definition of Done, деплой
на инфраструктуру заказчика.

### Added

- Парсер: страна хостинга (`meta.server_country`) определяется детерминированно из offline-базы MaxMind GeoLite2 по IP сервера, а не «знаниями» LLM; добавлены флаг CDN и уровень уверенности, чтобы не штрафовать вслепую за локализацию ПДн (#75).
- CI-гейт качества: автоматический прогон unit- и интеграционных тестов (crowler, backend, PDFreport, frontend) на каждый PR, контроль покрытия критических модулей (≥ 30 %), SAST-проверка (Bandit) и аудит зависимостей, защита ветки `main` обязательными проверками и ревью. Стратегия и критические модули — в `docs/testing.md` (#71).
- Сервис доступен онлайн по HTTPS на собственном домене (reverse-proxy Caddy + TLS-сертификат, #86); подготовлен деплой на инфраструктуру заказчика и сопровождение переезда DNS (#88).
- Качество как поддерживаемый актив: измеримые требования к качеству (`docs/quality-requirements.md`), автотесты к ним (`docs/quality-requirement-tests.md`), пользовательские приёмочные тесты (`docs/user-acceptance-tests.md`) и обновлённый Definition of Done с quality-гейтами.

### Security

- Парсер: недоверенный `sitemap.xml` внешних сайтов парсится через `defusedxml` — защита от XXE / billion laughs / внешних сущностей (#71).

## [1.0.0] - 2026-06-21

### Added

- Фоновый режим проверки: со страницы сканирования можно вернуться в главное меню,
  обход продолжается на сервере, а в истории скан помечается статусом «в процессе»
  (список сам обновляется до готового результата).
- Корневой `README.md` с описанием проекта, структурой монорепо и инструкциями запуска.
- `CONTRIBUTING.md` с описанием рабочего процесса (ветки, PR, релизы SemVer).
- `.env.example` со списком переменных окружения подсервисов.
- Шаблоны GitHub: PR-шаблон и issue-формы (User Story, задача, баг-репорт).
- CI Lychee для проверки ссылок в Markdown-файлах (на PR и push в `main`).
- Парсер публичных страниц (`crowler/`): формы, cookie, трекеры, политики, реквизиты оператора.
- Парсер: модальные/попап-формы и поля вне `<form>` теперь попадают в `pages[].forms`;
  детекция трекеров по cookie и путям телеметрии (gen_204, `/pagead/`, youtubei),
  сигнатуры Microsoft Clarity, TikTok Pixel, VK retargeting; детерминированная
  сортировка `pages`/`trackers`/`policy_documents` и ретрай страницы по таймауту.
- Микросервис генерации PDF-отчёта (`PDFreport/`) на FastAPI + Typst.
- Веб-интерфейс (`frontend/`): лендинг, экран сканирования, дашборд отчёта, история.
- Аутентификация (e-mail + OAuth Яндекс/ВК) и разовая оплата отчёта (CloudPayments).
- Соответствие 152-ФЗ самого сайта: cookie-баннер с кнопкой «Отклонить», согласие
  на обработку ПДн при регистрации, экран политики.
- Корневой `ErrorBoundary`: ошибка рендера показывает понятный экран с кнопкой
  «Перезагрузить» вместо белого экрана (#40).
- Доступность модальных окон (вход, тарифы): закрытие по `Esc`, focus trap,
  возврат фокуса на триггер, `role="dialog"`/`aria-modal` для скринридеров (#41).
- Видимый фокус клавиатуры (`:focus-visible`) на кнопках, ссылках, полях и
  навигации — кольцо в light и dark темах (#42).
- Уважение системной настройки «меньше движения» (`prefers-reduced-motion`):
  анимации отключаются/смягчаются (#48).
- SEO/шеринг: `<meta description>`, Open Graph-теги и favicon; шрифты грузятся
  через `preconnect`+`link` вместо render-blocking `@import` (#48).
- Тесты фронтенда: Vitest + React Testing Library + jsdom, скрипт `npm test`;
  покрыт `mapReport` (эталон + крайние случаи) и smoke-рендеры экранов (#49).

### Changed

- Тяжёлые экраны (`Report`, `Scanning`, `Pricing`) грузятся по требованию через
  `React.lazy` + `Suspense` — лендинг-чанк меньше (#44).
- Dev-панель твиков (`tweaks-panel`) исключена из прод-сборки: подгружается лениво
  только при `import.meta.env.DEV`, в проде тема/акцент/детализация — дефолты (#43).
- Сетевой слой `api.http()`: таймаут запроса (15 с) и `AbortController`, отмена
  in-flight запросов при размонтировании/смене отчёта, отдельный тост по таймауту (#45).
- Повторяющиеся inline-стили `Report.jsx`/`ReportAppendix.jsx` вынесены в
  переиспользуемые CSS-классы дизайн-системы (#47).
- В истории проверок клик по записи со статусом «в процессе» открывает экран хода
  проверки (с актуальным прогрессом) вместо уведомления «Отчёт ещё не готов» (#50).
- Блок «Суммарный потенциальный штраф» в отчёте поднят над счётчиками нарушений
  для акцента (#51).

### Fixed

- Перезагрузка страницы (F5) больше не выкидывает на главную — текущий экран
  сохраняется в `sessionStorage` (#15).
- Экран загрузки отражает реальный статус проверки: отчёт открывается только после
  фактического завершения скана на бэкенде, при ошибке показывается уведомление (#16, частично).
- Пустой раздел «Отчёт» (аккаунт без проверок) больше не показывает бесконечную
  загрузку — выводится сообщение «Отчётов пока нет» с кнопкой запуска проверки (#17).

### Security

- Полноценная защита краулера от SSRF (#37): запросы к loopback/private/link-local/
  reserved-адресам (IPv4 **и** IPv6, включая метадату `169.254.169.254`, CGNAT и
  IPv4-mapped) блокируются на сетевом уровне через перехват **каждого** запроса
  (`context.route`), а не только исходного URL — закрыт обход через 30x-редирект на
  внутренний адрес. Резолвятся все A/AAAA-записи (не первый IPv4) асинхронно (event
  loop не блокируется), а фактический IP origin'а повторно валидируется после
  навигации (`Response.server_addr`) — защита от DNS rebinding. Загрузка
  `robots.txt`/`sitemap.xml` (идёт мимо браузера, напрямую через httpx) проходит ту
  же проверку, включая **каждый редирект-хоп** — публичный URL или сокращатель,
  30x-редиректящий на внутренний адрес, не проходит. Дублирующая проверка на входе
  `/api/scans` (defense-in-depth).
